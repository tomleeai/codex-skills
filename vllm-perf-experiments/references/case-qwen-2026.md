# Qwen案例复盘：事实、失误与可推广方法

本例是2026-10进行的vLLM-Ascend/Qwen3.8-27B量化模型实验。以下是案例事实，不是新项目的默认参数或授权。服务器、账号、凭据与完整私有环境不随skill保存。

## 从头到尾

| 阶段 | 实际发生的事 | 决策与经验 |
|---|---|---|
| 定义问题 | 研究seqs和token预算对TTFT/TPOT/总输出TPS；短4096+2048、长131072+1024、名义前缀0.9；50请求/并发50 | 输入/输出和其他启动条件固定，区分请求均值与Common Metric吞吐 |
| 首服务器 | 预检和首轮遭外部SIGTERM；随后其他任务占卡，旧服务器有效正式轮为0 | 预检不进入参数结论；不终止其他任务，不降低原95%显存比例混跑 |
| 迁移 | 用户提供另一服务器；共享磁盘，但核对了命令、环境、核心commit与tokenization | 共享文件不保证运行环境相同，保存迁移审计 |
| 缓存排查 | 普通聊天预热受chunk/checkpoint影响；最终冻结117376真实token，896块对齐，并用非匹配guard验证 | 名义90%不是精确真实chat缓存比例；本次起始约89.51% |
| 协议修订 | 原验收要求运行命中89%–91%；完整50请求诊断初始缓存正确，随后命中85.86%、52抢占、50成功且输出正确 | 不用最终命中筛掉调度导致的缓存效应；诊断不算正式轮，修订有记录且发生在正式长序列开始前 |
| 串行执行 | 保存10轮有效结果后，用户要求多卡并行与低token巡检 | 在正式批次保存后交接；旧10轮只作独立参照，不混入新主测 |
| 四卡主测 | 4个独立TP1/DP1服务，各卡两项配置+同卡首尾基线，2负载×3正式轮，共96轮 | 这是实验并行，不是TP4或PD；隔离端口、物理卡、客户端可变文件和CPU mask |
| 余卡评估 | 另4卡空闲，但新卡补首基线需约43分钟，预计不能缩短剩余关键路径 | 不机械用满全部卡；扩卡成本和共享负载改变也影响可比性 |
| 完成 | 4800请求成功，48长轮起始缓存验证通过；恢复原服务，停止额外实例，health200 | 完成条件含数据有效、资源恢复、公开结果包和本地可读交付；自动跟进已删除 |
| 图表与讨论 | 交付12图，绝对值/同卡相对变化、min/max、尾基线；192个显示点值回查、离线测试 | 误差棒不是置信区间；不同卡分线，避免拼成一条全局最优曲线 |
| 后续审视 | 用户只是讨论补点，助手曾误当新增实验指令；实际未启动补测 | 对话意图是执行边界，讨论“还能怎样改进”不能触发任务扩张 |

## 数据支持什么

- 短序列seqs8→16→32时TPS617→831→1115（同卡），32→50/64时TPS1107→931/949（另一卡），并非一直增加。
- 长序列seqs16相对同卡32的TPS+26.6%、TTFT−13.8%、TPOT−33.5%；seqs8的TPOT更低但TPS较低。不能拼成未测16/2048。
- 短序列tokens预算TPS变化小；长序列tokens2048相对同卡16384的TPS+13.6%、TTFT−10.7%、TPOT−28.7%，不能概括所有负载“tokens影响很小”。
- 长实际命中84.14%–89.51%，参数效应包含缓存和抢占。保持模型、MTP3和原环境的causal_conv1d回退，不外推至修复后环境。
- 首尾TPS：短−1.76%至−0.53%，长−4.80%至+0.16%；卡3长尾基线CV7.54%。3轮不足以支持细微排名。

原生记录的1秒采样峰值：

| 负载/seqs | 活跃请求观测峰值 | KV观测峰值 |
|---|---:|---:|
| 短32 | 32 | 约76% |
| 短50/64 | 47 | 100% |
| 长8 | 8 | 约46% |
| 长16 | 16 | 约75% |
| 长32/50/64 | 23 | 近100% |

这是离散采样，不是严格硬上限。配合抢占数据，支持KV压力解释，但不证明纯计算饱和。请求/并发只有50，也限制了seqs50以上的趋势证据。

## 可以改进什么

1. **范围与点密度**：本次8/16/32/50/64在16–32、32–50缺少中间点，也缺少更高有效并发的另一负载协议。先宽扫再加密，比机械加几个大值更有价值；tokens倍增横轴已采用对数距离。
2. **机制证据提前入报告**：实际活跃/排队、KV峰值和抢占应与TTFT/TPOT/TPS一起聚合；不等用户质疑平台原因后才回查。
3. **更明确区分有限批次与稳态**：本例一次性50请求，TTFT含排队、TPS含批次尾部；后续容量研究需另设稳态/到达率实验。
4. **方差驱动重复**：在设计中声明有实际意义的差异及补测条件，避免仅凭三轮统一判定小差异。
5. **共享资源与时间顺序**：同卡基线降低卡间偏差，但未完全排除CPU/带宽与负载阶段干扰；可在预算内交错顺序、跨卡复核少量关键点。
6. **报告回查身份字段**：独立复盘发现本地报告两行基线的卡号与其数值不匹配，复盘时已依原记录更正；应逐行回查device/config/workload，而不只核对数值或曲线。原始正式记录和聚合数据仍为来源。
