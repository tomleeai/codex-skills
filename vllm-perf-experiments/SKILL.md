# vLLM性能实验

把“参数或拓扑改变了什么”与“测量是否可比”一起回答。交付简洁中文结论、可追溯逐轮数据和能表达趋势的图；不把运行现象过早解释为硬件极限。

## 先识别本轮意图

- **讨论/审视方案**：评价设计、说明证据缺口；不因“还能补几组吗”“是否认可”而启动压测、重启服务或创建自动跟进。
- **分析已有结果**：先用本地记录、日志摘要和原始指标；没有必要时不重新连接服务器。
- **执行/续跑**：按本轮及上下文已有授权推进。创建本skill不授予任何服务器操作权限，也不继承案例中的主机、账号、卡或显存设置。已有明确执行授权无需逐轮重问；新增范围与讨论状态不能由skill自行升级。

首次执行前落定模型/版本、资源所有权、负载、变量、验收、恢复目标和预算。可从[实验计划模板](assets/experiment-plan.json)取实际有用字段，不为填模板索取无关信息。

区分**case摸测**与**统计比较**：前者在稳定服务上寻找目标TPOT附近的高吞吐并发，默认整场开始用固定case跑2–3次预热/稳定性检查，此后每个新点正式测一次；后者按比较目的设计预热、重复数与漂移基线。用户约定优先，不能把统计比较的逐组预热和重复套到case摸测。

本仓库维护者已授权将本次及后续同类测试的非私密内容提交到共享仓库，并同步本地技能变动；不逐次重复请求相同发布确认。忠实保留测试参数、版本、过程、失败尝试、完整指标和原始字段，不以脱敏为由删减或改写性能数据。服务器账密、登录密钥、令牌及其他私密信息始终排除，适用范围见[仓库发布约定](references/knowledge-base.md#本仓库发布约定)。这不扩展服务器操作、其他仓库或无关内容的授权。

- **任务开始**：先用`locate`确认共享来源；按维护文档检查Git同步状态，不覆盖未提交修改。提取负载、模型/版本、TPOT、缓存或故障关键词，调用`scripts/knowledge_base.py search --query "<已脱敏关键词>"`；只展开最相关的1–5条。逐项核对适用条件、验证状态、版本和证据备注，再将可用经验纳入计划；无命中就按现有流程继续，不为填知识库额外跑实验。

## 关键决策

1. **先冻结问题，再冻结输入。** 区分单变量、交互效应、资源扩展实验；一次只改变声明的自变量。固定软件/启动参数、实际token长度、输出长度和客户端到达方式。拓扑改变必然伴随的因素要记录，不能假装仍是严格单变量。
2. **取点覆盖收益区、拐点和平台区。** 可先宽范围粗扫，再在拐点附近加密；不要只补几个大值。`max_num_seqs`是调度序列数上限，不是序列长度；`max_num_batched_tokens`是每次迭代的token预算。配置上限大于可用请求量时，平台不能证明设备饱和。
3. **控制可操纵的条件，记录内生结果。** 前缀实验分别记录名义共享比例、真实chat token边界、起始可复用缓存、运行命中率。缓存驱逐、抢占、重算和实际活跃数通常是调度结果，不因“不够漂亮”剔除。控制条件真正失败、外部请求、输出截短等仍需判无效并调查。
4. **预热、缓存构建和正式测量分开。** AISBench默认`data_num = 4 × concurrency`，用户明确协议优先。case摸测按整场预热规则执行，不在每个case/并发点前额外跑完整预热，不自动重测最终赢家。首次实际负载可兼作预检与独立预热，避免重复全量批次；单请求成功不代表并发可行。服务重启或改变影响稳态的配置后重新预热，仅SSH重连或切换case不自动触发。各点必要的前缀构建和计数器检查不属于模型预热，也不进入正式计时/计数。
5. **并行需要可比性和净加速。** 每条独立服务隔离物理卡、端口、客户端可变文件、输出与日志，并核对CPU/NUMA和共享资源。不同卡做不同配置时保留同卡基线和漂移检查；不能把卡间差异算作参数收益。新增基线/预热/调度成本大于节约时间时不扩卡。
6. **指标口径先核对。** TTFT/TPOT明确均值、分位数与单位，平均TPOT达标不等于P90达标。AISBench TPS取Common Metric总输出吞吐，不能用逐请求吞吐平均值替代。批次TPS=计入的输出token总量/统一测量时长；整轮耗时不同于请求平均E2EL，`single_*`也不天然代表真实单卡吞吐。CSV按声明的映射导出，保留原始字典，详见case流程。
7. **先保全记录，再恢复。** 先查进程、锁、状态和已保存轮次，避免重复派发。远程服务被停、SSH断开等导致无法继续时，在已有授权内最多尝试恢复3次；仍无法继续就保留现场、总结已有结果和断点，停止自动重试并等待人工介入。只停止能确认身份的自有服务；不用降低显存或混跑来绕过资源不足。恢复用户指定原服务/参数，并验证健康后才宣告完成；人工介入等待状态不算实验完成。

## 自动化与交付

让服务端脚本完成计数器差值、长度/成功数校验、逐轮原子写入和聚合；模型只处理精简状态、异常和最终解释。一次正常巡检通常只需状态、完成/目标轮次、worker存活、当前阶段、最近轮次和错误。仅在异常时读取对应日志片段。

已有结构化逐轮JSON时，可用只读工具先核查/聚合：

```text
python scripts/summarize_records.py <所选实验根目录> --glob "card*/runs/*/*_measure*.json" --expected-requests 50 --baseline baseline --output <分析输出目录>
```

脚本不连接服务器、不判定所有实验控制、也不解析任意版本AISBench原始表格。输入应是同一个已声明实验的记录；用`--protocol-id`补足缺失的协议标识，既有ID冲突会拒绝。拓扑/placement身份不完整时保留独立记录并警告，不聚为同卡均值、不计算配对变化；先补可追溯的元数据再比较。不要混入旧串行、迁移前或诊断。字段和用途见脚本`--help`。

最终只给能被数据支持的几条结论，附逐轮/汇总数据、同设备或同拓扑基线、缓存/抢占和未测范围。有重复时给离散程度；单次摸测不伪造误差范围或置信区间。图表优先绝对值与同基线相对变化两种视图，分卡/分拓扑连线，标明少量重复的范围不是置信区间。比较实测组合，不拼接两个单变量最优为未测组合。

分享/下载结果用明确文件清单，排除密码、token、私钥和原始私有环境。若本任务存在自动跟进，完成交付后按用户既有约定删除；不要为普通讨论创建新监控。
