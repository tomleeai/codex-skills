# DeepSeek-V4-Pro AISBench 性能测试

测试日期：2026-11-06（Asia/Shanghai）。表中指标采用 AISBench 最终 JSON，吞吐单位 tokens/s，TTFT/TPOT 单位 ms。

case_summary.json 包含七个目标：strict_selected 为 TPOT 不超过目标的最高实测吞吐；within_5pct_candidate 单列允许 TPOT 超出 5% 以内的候选。这是观察值，不能声称全局最优。两类候选的完整最终 JSON 分别保存在 selected_raw_results.json 和 near_target_raw_results.json。

每个新并发点正式测试一次，data_num=4×concurrency，request_rate=0。按用户修正后的要求，不再逐 case 预热或重复正式测试。前期已完成的预热单独保留在 stability_check.json，不混入正式最优值；单次正式观察不提供置信区间。4k 并发20的预热与正式吞吐约相差6%，并发48约相差0.035%，不足以证明整个测试期间无漂移。

非零前缀测试的缓存构建在正式计时及计数外进行。旧50%测试仅覆盖7/8个DP域，实际命中率约47.47%至48.41%；保留为历史观察，排除最终缓存候选。补测使用独立工具副本，以 X-data-parallel-rank 定向完成全部DP域的前缀构建；未修改原AISBench工具或服务脚本。

名义90%前缀的实际命中率为87.4446%，并未实测达到90%。每请求约131155个被查询token中，命中114688个；原因未在本轮确认。报告分别列名义比例和实测命中率，不能把该行作为严格90%命中率的验收结果。

按用户要求扫描既有日志并去重，没有重跑已完成并发。最初11:45:38的4k并发20结果TPOT19.4ms、吞吐905.8772已找到，并核对80条请求全部成功且均输出2048 token。该观察进入最高实测吞吐候选，但历史服务计数窗口不可恢复，其实际缓存命中率记为未知，不伪填为0。case_summary.json 的 source 和 validation_scope 区分日志恢复结果与带服务计数窗口的新记录。

all_trials.json 包含全部正式观察、请求数及输出长度验证、实际命中计数、重算吞吐和源文件哈希。所有正式输出均逐请求核对；预热、缓存构建及中止轮次不计入正式结果。原始日志留在实验过程目录；共享报告不包含原始地址、登录信息、人员标识或私有路径。
