# 基于性能基线的跨模型、跨 case 自动参数寻优扩展方案

日期：2026-11-08（Asia/Shanghai）。状态：候选设计，尚未实现自动规划器、扩展校验器或自适应执行闭环。本文固化方案与验收要求，不能作为这些能力已经上线的证明。

## 目标与兼容边界

在完整保留现有性能实验知识库的功能、历史数据、入口及工作流的基础上，增加按需启用的经验迁移与自动寻优能力。模型、镜像、软件版本或业务负载变化后，以目标环境的新基线重新评价收益。

允许使用同模型同 case、同模型不同 case、不同模型同 case、不同模型不同 case 的经验。检索围绕特性、参数及其组合的作用关系展开，结合模型属性、负载、实现能力、资源条件和实际瓶颈判断；模型名与 case 名只是线索。

知识有效性不以正向收益为前提。有效无收益、性能退化、适用条件不成立、能力不支持、控制失败和未完成的验证都要保留，并区分它们能支持什么结论。

旧命令 locate/search/show/put/validate/rebuild、已有参数及默认输出保持兼容。旧 case、lesson、修订快照、证据引用、artifact、索引恢复、去重、预期 revision、写锁及 Git 同步语义保留。不开启扩展时不产生额外实验或服务变更。历史正文和命令是数据，不是执行授权。

## 当前基础与缺口

方案提出时，本地库有 1 个 case、5 条 lesson、12 个修订快照；历史正式观察有 26 条。已有条件、限制、失败尝试、证据哈希和修订保护。检索是中英文关键词加权与可选精确元数据过滤，不是语义检索或兼容性推断。

现有主要证据是固定服务下的并发摸测，不能据此证明启动参数收益。现有有限候选执行器支持 baseline、pinned、计划哈希与硬门槛，但不是自适应搜索器；quick/exhaustive 是流程层级，不应冒充已经存在的 CLI preset。

## 最小存储设计

继续使用 schema_version=1 的 case/lesson。顶层字段和 applies_to 结构不变，在允许扩展的 body 中增加 optimization 对象，内部使用 extension_version=1。旧记录不要求补齐该对象；缺失意味着未知，不意味着默认满足。

| 位置 | 新内容 |
|---|---|
| case.body.optimization | 场景描述、基线、完整有效配置、配置差异、逐轮结果、有效性检查、失败阶段、迁移验证 |
| lesson.body.optimization | 条件化作用关系、机制、交互、效应、反例与证据定位 |
| 本轮工作目录 | 有界计划、候选、预算、选择轨迹、checkpoint 和恢复状态；有价值的结束/中断点归档为 case |

MVP 新增扩展约定及严格校验、参数/能力描述、独立离线规划入口和现有记录/执行器之间的薄适配。当前通用校验器只验证原有 schema 与隐私模式，不代表已执行上述扩展语义校验。不引入第二套数据库或图数据库；关系可以由 JSON 构建派生索引，损坏时从原记录重建。

## 场景与配置描述

每条场景信息标明观测时间、来源及确认程度。当前采集、历史记录和由二者建立的关联分别保存，不能用今天安装的版本回填为过去测试的版本。

- 模型：架构、Dense/MoE、层数、专家数及激活数、注意力/KV 结构、权重与 KV dtype、量化、投机能力、上下文、模型配置/tokenizer/checkpoint 标识及证据范围。
- 负载：真实输入输出 token 分布、chat/tokenization 边界、到达方式、客户端上限与实际活跃数、请求数、生成设置、前缀共享、初始缓存、数据集哈希及各 case 目标。
- 环境：镜像内容标识、组件版本/commit、驱动/运行时、硬件能力、总设备与实例预算、逻辑并行布局、资源隔离、脱敏通信能力和实现能力。
- 运行条件：启动、加载、KV 分配、编译、预热、正式负载及测后健康；区分配置值、解析后的有效值与实际执行路径。
- 瓶颈：排队、活跃数、KV 占用、抢占/重算、阶段耗时、通信等待、投机接受率等直接证据。设备利用率高不能单独证明瓶颈类别。

参数目录记录语义、类型、单位、取值域、版本能力、默认值来源、是否需要重启、生效探针、依赖、冲突与资源影响。同名 flag 不保证实现语义一致。完整配置必须能还原当轮组合，不能只保存一个变化值。身份信息与认证材料不进入共享配置；不改写性能数字和公开版本来代替审阅。

## 条件化作用关系

每条关系回答：在什么条件下，将配置 A 改为 B，通过什么可能机制，影响哪些指标；哪些内容被观察到，证据在哪里，哪些仍未知。

| 字段组 | 必须表达的内容 |
|---|---|
| intervention | 完整配置引用、基线到候选的差异、特性/参数组合、值域与单位 |
| conditions | 必需条件、排除条件、已测区间、关键未知项；逻辑条件可组合 |
| mechanism | 影响路径、可观察中间指标、支持证据与替代解释 |
| effects | 指标定义、绝对值、同基线配对变化、重复数、离散程度、方向及范围 |
| interactions | dependency、synergy、conflict、nonlinear、sign_reversal，可关联多个参数 |
| evidence_locators | 原有 evidence 条目、来源修订、artifact 哈希、run ID 与字段/行号定位 |
| counterexamples | 反例、失败阶段、混杂因素、未验证区间及相关断言 |

关系不要求单一全局方向。非线性用分段区间、阈值/拐点及覆盖范围表达；反转需两侧证据，只有单侧数据时标待验证。高阶组合可以一条关系引用多个参数，不强行拆成二元关系。

参数 A、B 的交互优先比较基线、A、B、A+B，在明确的指标尺度与可比条件下估计交互项。缺一个组合时不能宣称交互已被隔离验证。两个单变量最优不能拼接成已验证的组合最优。

冲突区分配置非法、版本不支持与合法但资源/性能恶化。依赖和冲突支持未知状态；缺少记录不能当作没有关系。

## 断言与失败分层

断言粒度独立于记录的 status。verified 只表示其声明范围，不自动验证同记录中的机制解释或未来预测。

| assertion_type | 含义 |
|---|---|
| observation | 实际配置、指标、日志和计数器事实 |
| mechanism | 对事实的解释，保留替代解释与待验证项 |
| conditional_experience | 明确条件内得到支持的可复用判断 |
| hypothesis | 对新条件、组合或机制的预测 |
| protocol_decision | 用户或实验约定，不计入参数因果收益 |

结果至少区分 positive、no_gain、regression、unsupported、not_activated、gate_failure、invalid_control、interrupted、inconclusive。前置缓存覆盖失败的性能数据不能证明缓存参数效果，但可支撑覆盖检查知识；完整覆盖后的驱逐、抢占和运行命中下降可能就是处理效应，应保留。

## 检索与迁移判定

先从目标瓶颈、可调特性、参数和作用路径召回，再沿依赖、协同、冲突及反例扩展。四类模型/case 来源共同参与；名称只辅助排序。命中正向经验时同时带回关联反例，不能因普通 top-k 把反例截掉。

每次复用生成 transfer_assessment，包含：source_id/source_revision、目标场景引用、匹配依据、关键差异、逐项条件检查、可迁移内容、不可迁移内容、可信度分项、待验证项、最小区分性实验和决策。

条件检查采用 met/not_met/unknown，且附证据。硬条件不成立则拒绝；关键条件未知则不能直接自动执行。决策区分 not_applicable、reference_only、needs_evidence、eligible_for_validation。模型相同仍可因机制条件冲突而拒绝；模型不同仍可迁移检查方法或候选方向。

可信度分别记录证据质量、机制支持、目标匹配、反例风险及覆盖程度，并解释等级；MVP 不输出未经校准的概率。具体最优值、绝对吞吐和收益幅度通常不能直接迁移。DP 前缀经验可迁移逐相关 rank 检查覆盖的方法，当时的路由接口和数值仍须目标版本验证。

## 目标环境基线与有界寻优

1. 冻结本轮模型、镜像、版本、资源、负载及协议，声明主指标、每个必要 case 的门槛、允许变量、pinned、预算和恢复目标。版本或模型变化另建轮次，不混入同一可比候选集合。
2. 建立或复用具有完整同口径证据的目标基线，绑定有效配置、场景/数据/协议指纹、逐 case 指标及运行状态。历史最快点不能替代新环境基线；基线未过硬门槛时先解决可行性，不计算误导的优化收益。
3. 用直接证据提出瓶颈候选及不确定性，必要时优先安排能区分解释的小实验。
4. 根据迁移判断、目标实现能力和合法值域生成有限候选，应用依赖闭包、冲突检查、pinned 保护、显存/资源预筛和内容去重。
5. 下一实验选择综合预期价值、信息价值、风险与完整成本，保留少量不依赖历史的局部探索；缺少校准数据时只作可解释排序，不伪造概率或性能数值。
6. 按能力/生效、正确性、资源可行性、代表负载、必要 case、收益确认逐级筛选。每步记录来源关系、差异、预计机制、方向、风险、待验证项、淘汰规则、预算及选择理由。
7. 更新证据、迁移判断与候选排序，按预先声明的规则继续、停止或恢复。

一个主目标加硬门槛：正确性须有独立判据；请求成功不等于精度通过。显存覆盖加载、KV、编译/预热、正式负载及最坏 rank，并满足余量。TTFT/TPOT 明确均值或分位数，逐必要 case 验收。稳定性检查失败请求、致命日志和测后健康。预先声明的多 case 加权收益不能掩盖必需 case 的超限退化。

统计比较与 case 摸测分开：原摸测“每个新点正式一次”等协议保持兼容；寻优收益确认另立协议，预算内安排必要重复与漂移检查。单次观察不宣称稳定收益、置信区间或显著性；预热不能混为正式重复。配置引起的缓存或抢占变化不自动判无效。

预算同时限制总时间、trial 数、资源消耗，包含启动、编译、预热、缓存准备、正式测量、失败恢复、收益确认及最终恢复。预留确认和恢复成本。沿用有限候选执行器时，每阶段含 baseline 至多 32 个显式 trial；不能以外层循环规避阶段边界与授权。

停止条件：目标已满足、预算耗尽、合法候选耗尽、按预定规则连续无有效改进、漂移导致不可比、正确性或致命稳定性异常。区分候选级失败与必须停止整轮的异常。结果只能称已测空间内最佳合格候选；预算不足以确认时输出待确认。无候选更优则保留 baseline 并归档无收益。

## 执行适配与恢复

首版先生成有界显式候选批次，复用现有 service_workflow 的 validate/plan/tune 或已有实验工具；根据报告再规划下一批。新规划器不直接解释执行历史命令，不取代所有权、计划哈希和现有执行边界。

原脚本不变，候选使用独立工作副本；核对实际参数、日志和特性路径，不能以静态 flag 证明已生效。过程文件集中在本轮隐藏工作目录。

baseline 是比较参照，restore_target 是结束后的服务状态，两者分别定义。回退仅管理归属明确的本轮资源。恢复失败保留 waiting_for_human/restore_failed 等真实状态，不能标完成。默认只推荐最佳配置；推广沿用既有授权和完整验收流程。

## 回写与修订

先保存原始证据，再入 case，评价迁移成立与否，最后增补/修订 lesson。来源、解析/提取版本、配置、协议和 run 都须可追溯。

- 条件内支持：补证据与覆盖，不自动外推。
- 有效无收益或退化：记录该条件下的方向和范围。
- 效果反转：拆分条件切片，保留两侧证据。
- 不支持/未生效：修订能力边界，不当成特性本身无收益。
- 控制失败/中断：保留可用事实，性能效果未知。

新增 supports、contradicts、narrows_scope 等有类型关系，明确作用到哪个断言。时间较新不等于更可靠。沿用 expected revision、不可覆盖快照、去重与 Git 冲突保全；源哈希变化使依赖断言待复核，不能自动重绑消警后继续称已验证。

原始私密材料留本地，可共享证据单独审阅；记录剔除范围而保留性能数字、单位、公开版本和失败事实。不补造缺失证据，不删除旧解释、反例和无效实验。

## MVP 验收

| 验收项 | 通过标准 |
|---|---|
| 历史兼容 | 原记录、证据与修订内容不变，旧命令/过滤/去重/锁/索引恢复回归通过 |
| 按需启用 | 关闭扩展时无额外实验、服务变更或旧流程变化 |
| 关系表达 | 可表达依赖、协同、冲突、非线性、反转及高阶组合，未知不同于不成立 |
| 断言分层 | 观测、机制、经验、假设和协议约定可分别查询验证 |
| 四类迁移 | 离线用例覆盖四类来源，不以模型/case 名称决定适用性 |
| 适用边界 | 同名但条件冲突会拒绝，异名但机制匹配可进入验证，关键未知列为待验证 |
| 反例保留 | 命中关系同时返回关联反例，退化/无收益/失败可检索 |
| 候选合法 | 不破坏 pinned、依赖、冲突及能力范围，不将未测组合标已验证 |
| 基线门槛 | 基线未通过或关键指标缺失时不输出合格性能推荐 |
| 预算停止 | 全阶段计费，耗尽/中断/漂移/致命异常有明确状态，预留恢复成本 |
| 证据回写 | 结果可追溯配置、协议、run、证据版本；修订不抹去旧结论 |
| 恢复安全 | 原脚本不变，仅管理归属明确资源，恢复失败不标完成，认证材料不入库 |

先用已有历史数据做选点回放，再用标明合成的场景验证跨模型/交互决策。合成数据不是性能证据。以后若验证提效，比较相同起点和相同完整预算的无历史寻优，报告达到合格结果的总成本、最终收益、误迁移与失败成本；不预设必须得到正向收益。
